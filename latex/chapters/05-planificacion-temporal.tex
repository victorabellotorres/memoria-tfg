La planificación cubre el proyecto completo, desde la definición del protocolo
experimental hasta la defensa. Se adopta un enfoque iterativo e incremental:
el trabajo se divide en tareas verificables, cada una con un objetivo,
predecesoras, recursos y una estimación de horas. El progreso se revisará
semanalmente mediante el diagrama de Gantt y el tablero Kanban. En cada revisión
se actualizará el esfuerzo restante y, cuando un imprevisto o riesgo afecte a la planificación
o al cumplimiento de un hito, se revisará el plan y se valorarán cambios.

\section{Tareas}

Las tareas se describen primero para concretar el trabajo que comprende cada
una. Después, la tabla~\ref{tab:tareas-proyecto} resume únicamente su título,
las horas, las predecesoras y los recursos asignados.

El código de cada tarea indica su tipo:
\begin{itemize}
  \item \textbf{EP} Estudio Previo
  \item \textbf{GEP} Gestión del Proyecto
  \item \textbf{DT} Desarrollo Técnico
  \item \textbf{AR} Análisis de Resultados
\end{itemize}

\subsection{Criterio de estimación y contingencia}

Las horas de la tabla~\ref{tab:tareas-proyecto} ya incluyen un pequeño margen
para resolver imprevistos. Ese margen es mayor en las tareas menos previsibles,
como el entrenamiento, la conversión y la validación \emph{edge}, y menor en las
tareas rutinarias o ya realizadas. No se añade una bolsa separada por encima de
las 540 horas.

Las 540 horas ya están completamente distribuidas, por lo que no existe margen
adicional fuera de la tabla. Si una tarea supera su estimación, el exceso se
compensará reduciendo primero trabajo opcional, como el demostrador o una
búsqueda extensa de hiperparámetros. Si esta reducción no basta, se acordará con
la dirección qué parte del alcance debe recortarse y se actualizará la
planificación.

\section{Control de seguimiento}
\label{sec:control-seguimiento}

Los hitos M1--M4 se utilizarán como puntos formales de control del seguimiento.
En cada fecha objetivo se comparará el criterio observable con el estado real,
las horas consumidas y los riesgos abiertos. Si un criterio no se cumple, se
registrará la desviación y se activará una replanificación o el plan alternativo
correspondiente antes de continuar con el siguiente hito.

Además, cada semana se registrarán para cada actividad las horas planificadas,
las horas reales y una nueva estimación del trabajo restante.

recurso humano R1 y asume cuatro roles, identificados mediante las opciones

\section{Seguimiento y gestión de riesgos}
\label{sec:gestion-riesgos}

\begingroup
\small

Todo proyecto presenta riesgos que pueden alterar su desarrollo. Por ello, cada
semana se comparará el avance real con la planificación y se revisará si alguno
de los siguientes riesgos se ha materializado. Las probabilidades indicadas son
estimaciones de planificación, no frecuencias observadas. Estas probabilidades
describen la posibilidad de que ocurra un problema y no deben confundirse con
el margen ya incluido en la planificación de las horas. Si fuera necesario
reducir el alcance, se conservarán la comparación experimental, la memoria y la
validación de al menos un modelo en un entorno \emph{edge}; las extensiones
opcionales serán las primeras en descartarse.

\begin{description}[leftmargin=0.45cm,labelindent=0cm,style=nextline,
  itemsep=0.2\baselineskip]
  \item[\textbf{Dificultades técnicas inesperadas.}]
  Se estima una probabilidad del 30\,\% y un impacto medio. Se trabajará de
  forma incremental y con pruebas tempranas. Si aparece un problema, se usará el
  margen incluido en la tarea y después se reducirá el trabajo opcional.

  \item[\textbf{Recursos de cómputo insuficientes.}]
  Se estima una probabilidad del 20\,\% y un impacto medio. Primero se reducirá
  la búsqueda de hiperparámetros, la resolución o el tamaño de lote. Si no basta,
  se recurrirá a cómputo externo bajo demanda para aumentar la capacidad de
  cómputo disponible.

  \item[\textbf{Generalización pobre o error elevado.}]
  Se estima una probabilidad del 20\,\% y un impacto alto. Se usarán particiones
  comunes, controles de fuga y técnicas de regularización. Si el error sigue
  siendo alto, se analizará y se presentará como una limitación del estudio.

  \item[\textbf{Problemas con los datos, el almacenamiento o el equipo.}]
  Se estima una probabilidad del 10\,\% y un impacto alto. Se comprobará la
  integridad de los datos, se conservará una versión piloto y se harán copias de
  seguridad del código, las configuraciones y los resultados.

  \item[\textbf{Incompatibilidad con el entorno \emph{edge}.}]
  Se estima una probabilidad del 15\,\% y un impacto alto. La conversión se
  probará con antelación. Si algún modelo no resulta viable, se intentará
  cuantizarlo o se probará otro modelo eficiente y se documentará la limitación.
\end{description}
